# 基于深度学习的网络入侵检测系统

## 中期开发与二人分工约定

本文件用于《编程能力提升》课程项目的组内开发、交接与中期汇报。成员暂用 A、B 代称，预计工作量各占 50%。本文为开发计划，完成状态需要依据实际代码和运行结果更新。

项目采用 Python，读取公开网络流量特征数据，以多层感知机（MLP）作为深度学习主模型，随机森林作为对照基线，识别正常和攻击流量，并通过本地浏览器界面展示预测结果、误报漏报与模型指标。

## 1. 中期目标

中期形成一个可运行的小型原型，完成“导入数据 → 加载模型 → 批量检测 → 查看指标 → 查看错误样本”的完整流程。

| 层次 | 本阶段交付 |
| --- | --- |
| 基础流程 | CSV 导入、字段检查、预处理、随机森林训练与预测 |
| 模型比较 | MLP 首轮训练与预测，两模型在相同评估集上的五项指标 |
| 界面演示 | 文件选择、模型选择、检测进度、结果表格、误报漏报筛选 |
| 汇报材料 | 数据划分说明、系统结构、实际结果截图、两人贡献、下一步计划 |

中期优先完成二分类。未知攻击检测、阈值交互、推理延迟与概念漂移分析列入后续计划，按进度选择拓展。

## 2. 技术与数据约定

技术方案暂定 Python + pandas + scikit-learn + PyTorch + Streamlit。pandas 负责 CSV 与数据整理，scikit-learn 负责预处理和随机森林，PyTorch 实现 MLP，Streamlit 提供本地浏览器界面。开发开始时统一 Python 与依赖版本，使用独立虚拟环境，并提交固定依赖版本的 requirements.txt。

MLP 初始结构拟采用“输入层 → 32 → 16 → 1”，隐藏层使用 ReLU，训练时输出 logits，搭配 BCEWithLogitsLoss，预测时经 sigmoid 得到攻击得分。最终参数和训练轮数以真实运行记录为准。中期先支持 CPU 运行，记录随机种子、设备和依赖版本。

预处理器和随机森林使用 joblib 保存，MLP 保存 state_dict，并同时保存网络结构、预处理器、输入字段顺序及编码后的维度。加载 MLP 时重建相同结构，加载权重并进入 eval 模式，在关闭梯度计算的情况下推理。

数据采用 UNSW-NB15 提供的 CSV 训练集、测试集。下载入口见 [UNSW-NB15 官方页面](https://research.unsw.edu.au/projects/unsw-nb15-dataset)。

- 保留官方测试集，从训练集划出约 20% 作为验证集，固定随机种子 42，保存划分记录。检查划分间的重复特征记录，记录发现数量与处理方案。
- 中期调试和模型比较以验证集为主。测试集留作参数确定后的最终评估。
- label 用作二分类真实标签，0 表示正常，1 表示攻击。attack_cat 用于分组分析，id 用于辅助追踪，三者均从模型输入中排除。
- 缺失值填充值、类别编码表、标准化参数仅在训练集拟合。验证和检测阶段复用已保存的处理流程，遇到新类别使用约定的未知类别处理方式。
- 统计正常与攻击的数量。若尝试类别加权或重采样，仅在训练集操作，并保留未处理时的基线结果。
- 首轮可用固定抽样的小规模数据跑通流程，报告中注明抽样方法、样本数量和随机种子。模型比较使用同一批评估记录。

## 4. 交接接口

### 数据对象

| 对象 | 字段或内容 | 约定 |
| --- | --- | --- |
| FlowRecord | record_id、feature_values | 特征按字段名传递，由预处理器按训练时固定顺序转换 |
| FlowLabel | record_id、true_label、attack_category | 单独交给评估模块，按 record_id 对齐 |
| PredictionResult | record_id、model_name、attack_score、predicted_label、threshold | attack_score 范围为 0～1，代表模型输出的攻击得分 |
| EvaluationResult | TP、TN、FP、FN、五项指标、有效样本数 | 由 B 统一计算，A 参与核对 |

record_id 在每份导入数据内唯一。生成编号时保留原始行号映射，便于回查。无标签数据支持预测，指标计算和误报漏报筛选仅对有标签记录开放。

### 模型调用

共同约定模型适配器的批量预测接口。以下为接口示意，具体实现由 A 完成。

```python
from typing import Protocol
import numpy as np
import pandas as pd

class DetectionModel(Protocol):
    model_name: str

    def predict_attack_scores(self, features: pd.DataFrame) -> np.ndarray:
        ...
```

features 仅包含输入特征列。返回一维数组，长度与输入行数相同，顺序与输入一致。B 保留对应 record_id 并构建结果表。特征列缺失或无法转换时抛出明确异常，由界面显示原因。FlowRecord、FlowLabel 等是逻辑数据约定，可使用 DataFrame 和字典实现。

A 实现两个模型适配类，并提供加载完整模型包的入口。B 根据得分作告警判断，统一使用 attack_score >= threshold 时预测为攻击。中期阈值先固定为 0.5，使用的阈值写入导出结果。

模型输出攻击得分时，随机森林必须根据 classes_ 找到标签 1 对应的概率列，MLP 使用单个输出经 sigmoid 得到的得分。两个模型使用一致的标签含义。得分只用于模型判断与阈值比较，界面称为“攻击得分”。

第一轮交接包含一份小规模验证 CSV、真实标签、一个随机森林模型包、调用示例，以及该批数据的预测结果。MLP 接入后复用相同接口。

## 5. 指标计算约定

统一把攻击作为正类，指标内部使用 0～1 的小数，界面转换为百分比。

| 统计项 | 含义 |
| --- | --- |
| TP | 攻击被正确检测为攻击 |
| TN | 正常被正确判断为正常 |
| FP | 正常被误报为攻击 |
| FN | 攻击被漏报为正常 |

| 指标 | 公式 |
| --- | --- |
| 准确率 Accuracy | (TP + TN) / (TP + TN + FP + FN) |
| 精确率 Precision | TP / (TP + FP) |
| 召回率 Recall | TP / (TP + FN) |
| F1 | 2 × TP / (2 × TP + FP + FN) |
| 误报率 FPR | FP / (FP + TN) |

分母为零时显示 N/A，导出时保留空值并注明原因。无法解析的记录给出行号和原因，统计排除数量。

核对样例使用 TP=40、TN=50、FP=5、FN=5。预期准确率为 90%，精确率、召回率和 F1 均约为 88.89%，误报率约为 9.09%。A、B 共同核对这一样例后接入真实结果。

仅点击“开始检测”触发加载与推理；结果、运行配置和指标保存于 `st.session_state`。切换页签、筛选、详情和下载复用结果；改变数据内容、模式、模型、版本、特征约定或分批大小后隐藏旧结果及其下载按钮，提示重新检测。一次重新运行替换整个上次运行，不追加；如需保留双模型比较，应同时选择两个模型重跑。结果仅保存在本次浏览器会话，重启后需重新检测；可下载 CSV 手动保存至 `results/`。

数据标识为原文件内容的完整 SHA-256；同内容改名仍被识别为同数据。`record_id = 文件哈希:顺序号`，不依赖原始 `id`；`source_row` 为含表头的 CSV 物理起始行号，支持空行和引号内换行。原始字段保留；与结果字段冲突时用 `input_` 前缀展示，原始记录详情始终来自未改写的导入数据。

输入排除 README 约定的标签/id，以及运行元数据、预测结果和评估字段。真实模式按 A 特征清单选列并排序，检查 numeric/categorical 类型；空字段保持缺失，不拟合或填补，由 A 的已拟合处理器负责。CSV 的 `NA` 等文本原样保留，避免非法标签被记作缺失。标签优先使用 `label`，也支持 `true_label`；类别优先使用 `attack_cat`，也支持 `attack_category`。仅能解析为 0/1 的非空标签参与评估，缺失与非法标签分别计数。模型返回非法得分时整个批次失败，保留模型、原始行号范围和原因；其余批次继续，不将失败记录归类为正常。

顶部统计按“记录 × 模型”计数，并明确显示独立流量数。模型独立评估报告各自成功、失败、参与评估、缺失及非法标签数；双模型比较图和比较表仅用双方共同成功且标签有效的 record_id，注明共同样本数。分母为零返回空值，界面显示 N/A，导出 `*_reason` 说明原因。类别表仅统计真实攻击，失败单列；分歧表只比较双方预测成功的记录。

导出包括当前筛选的全部匹配记录（不限于当前页）、完整预测、指标比较三个种类；均含数据集身份、运行模式、模型版本及阈值。调试结果的 `run_mode=debug`、`data_notice=界面调试数据` 与文件名共同标记，不可进入真实实验报告。指标文件 `scope=individual` 为各模型独立评估，`scope=common` 为共同样本评估；数值仍为 0～1，未四舍五入。当前筛选导出保留排序。

## 10. 深度学习主线的 B 端增补（2026-11-18）

本次按 B 的职责完善展示与评估，不增加训练实现。已检查远程 `main`：最新提交是合并此前的 B 分支，没有 A 新交付的模型代码或权重。前一版的中文注释继续保留，新函数与功能块同样有简短说明。

MLP 在模型选择中优先排列，默认指标关注 MLP；随机森林作为基线，两者仍可同时检测。增加首个“深度学习分析”页签，原有检测概览、流量记录和误报漏报分析继续保留。

新增功能：

- **ROC 与 PR**：从当前 MLP 的已有得分计算曲线，标出固定阈值 0.5 的位置；只使用预测成功、得分有效、标签为 0/1 的记录，同分样本一起处理。
- **ROC-AUC 与 AP**：AUC 用 ROC 梯形面积；AP 按召回率增量加权精确率，使用非插值定义，不能用 PR 梯形面积代替。指标比较 CSV 的 individual/common 两种口径均增加这两个值、原因及排序评估数量。
- **得分分布**：按真实正常、真实攻击、标签缺失和标签非法分组，明确标出 0.5 阈值。缺失标签仍可进入分布分析，但不能进入 ROC/PR 评估。
- **边界样本**：调整阈值附近的观察范围，查看与 0.5 距离最近的记录；只改变筛选视图，不改变预测标签，不重新推理。可下载完整边界样本和曲线点 CSV。
- **共同样本基线对照**：MLP 与 RF 的 AUC/AP 对照和原有五项指标一致，只比较共同成功且标签有效的 record_id。
- **训练记录展示**：检测开始时读取 `models/mlp_training_report.json` 并核对模型版本，保存本次快照；可展示 A 实际记录的网络结构、配置、训练/验证 Loss、可选验证 F1/Accuracy，以及记录 CSV/JSON 下载。缺失、模板、版本不符或数值非法时提示原因，不阻止检测。

ROC-AUC 在缺少正常或攻击类别时显示 N/A；AP 在没有有效攻击记录时显示 N/A。只有攻击记录时 AP 可计算，但界面提示这不足以说明区分正常流量的能力。当前阈值仍固定为 0.5；分析曲线的 `score_threshold` 只是绘图切分点（`inf` 是无告警起点），不改变导出预测中的 `threshold=0.5`。得分也不等于已校准的攻击概率。

新增文件：`deep_learning_view.py`（MLP 分析页）、`training_report.py`（报告校验）、`data/mlp_training_report.example.json`（空模板）、`tests/test_deep_learning.py`（针对性测试）。依赖不变，无需为 B 新安装 PyTorch 或 scikit-learn。报告模板和 A 的字段约定见 [models/README.md](models/README.md)。

默认调试模式仍只使用固定得分，不生成训练曲线。测试代码里的人工训练记录仅用于验证展示分支，不作为项目训练结果。训练报告文件、真实预处理器和权重仍待 A 交付。

讲给老师时，可以按下面的主线说明：

1. **MLP 是主模型**：A 负责让网络从训练数据中学习权重，B 将其批量得分接入检测系统；随机森林提供基线对照。
2. **阈值与排序分开看**：五项指标评价 0.5 阈值下的告警；ROC-AUC/AP 补充观察不同切分点下的排序表现。
3. **分析模型哪里容易错**：用得分分布、边界样本、误报/漏报和攻击类别定位实际问题，不根据单个高分推测攻击原因。
4. **训练过程有依据**：收到 A 的同版本报告后，展示实际损失曲线和验证指标；最终效果仍由当前检测数据的评估说明。

计算定义参考官方 [ROC 曲线文档](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.roc_curve.html) 和 [AP 定义](https://scikit-learn.org/stable/modules/generated/sklearn.metrics.average_precision_score.html)。本项目按这些定义使用 NumPy 计算，没有新增 scikit-learn 依赖。
